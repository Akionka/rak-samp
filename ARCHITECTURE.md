# Architecture

Each ASI loads independently. Only the host links the native hook backend;
plugins use the public, versioned SDK package.

## Structural ownership

The public SDK root is a re-exporting facade: `types.rs`, `abi/mod.rs`, `api.rs`,
`resolve.rs`, and `subscriptions.rs` own safe values, the C ABI declarations,
safe wrapper glue, host discovery, and callback ownership. Win32 keeps host
composition state in `mod.rs`; `backend.rs`, `lifecycle.rs`, `tick.rs`,
`cache_lifecycle.rs`, `native_abi.rs`, `commands/`, `requests.rs`, `refresh.rs`,
`native_bitstream.rs`, and `hooks.rs` own forwarding, SA-MP lifecycle,
participant snapshot/pump work, command execution, coherent cache publication,
raw ABI adaptation, native string/bitstream handling, and callbacks used by the
`samp-native` detour entry points.
`crates/gta-sa-native/` owns GTA game-process ordering, detour restoration,
typed/evidence-bearing GTA profile facts, guarded x86 calls and vtable
resolution, verified native layouts, local-ped snapshot/teleport operations,
and the `CPools` reference-conversion targets. `crates/gta-sa/` owns pointer-free
values plus callback-scoped and queued safe GTA facades.
`crates/samp-native/` owns the four immutable SA-MP profile specifications,
their verified layouts, limits, RVAs, ABI strategies, exact identity selection,
guarded SA-MP memory helpers, singleton/connection/pool/player/UI operations,
GTA-handle mappings, and RakClient hook installation, detour entry points, and
vtable restoration. The crate forwards hook events through one process-lifetime
host callback table; listener dispatch and captured-original calls remain host
composition. One selected profile drives every cache refresh and game tick for
R1, R3-1, R5-1, and DL-R1.
Host listener registration and callback dispatch live in
`host_api/listeners.rs`, while native chat-command callback slots and teardown
synchronization live in `host_api/chat_commands.rs`; the root retains the
exported entry point and
ordered ABI table.
