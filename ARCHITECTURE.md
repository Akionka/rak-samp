# Architecture

Each ASI loads independently. Only the host links the native hook backend;
plugins use the public, versioned SDK package.

## Structural ownership

The public SDK root is a re-exporting facade: `types.rs`, `abi/mod.rs`, `api.rs`,
`resolve.rs`, and `subscriptions.rs` own safe values, the C ABI declarations,
safe wrapper glue, host discovery, and callback ownership. Win32 keeps shared
state in `mod.rs`; `backend.rs`, `lifecycle.rs`, `tick.rs`,
`cache_lifecycle.rs`, `native_abi.rs`, `commands/`, `requests.rs`, `refresh.rs`,
`native_bitstream.rs`, and `hooks.rs` own forwarding, lifecycle, tick ordering,
command execution, cache publication, raw ABI values, native string/bitstream
handling, and hook patching. `native_client/` selects the immutable direct profile
separately from networking offsets. One `NativeClientProfile` drives every
cache refresh and game tick for R1, R3-1, R5-1, and DL-R1. The four profile
specifications contain verified layouts and narrow strategies; shared modules
own singleton lookup, native aliases, textdraws, handle lookups, and the
capability-oriented `players/` and `ui/` operation trees. Host listener
registration and callback dispatch live in `host_api/listeners.rs`, while
native chat-command callback slots and teardown synchronization live in
`host_api/chat_commands.rs`; the root retains the exported entry point and
ordered ABI table.
